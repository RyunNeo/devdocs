# 本地生产环境演练（阶段 6）

前期按用户要求分步教学；2026-10-16 用户明确授权助手接管后续本机部署与验收。
操作与当前验收进度见 [演练指南](../../docs/stages/06-local-production-guide.md)。

当前原演练环境与独立恢复环境均已启动并通过健康检查；backup-001 成对备份已经实际还原到新项目。
恢复后的迁移版本、业务表数量和逐文件哈希已核对，恢复库旧登录会话已清除；原库计数和文件哈希不变。
七项生产入口浏览器测试在恢复环境通过，包括注册登录、上传预览、移动布局和空库本地问答用量。
这不等于公网部署、真实模型验收，或此前缺少对照记录的强制重建持久化测试完整通过。

- compose.rehearsal.yml：独立演练栈，不修改根目录开发数据库配置。
- api.Dockerfile / web.Dockerfile：非 root 生产运行镜像。
- config.py：生成独立配置，不覆盖已有配置、不读取开发密钥。
- maintenance profile：显式执行的一次性上传目录初始化与数据库迁移。
- backup.py：本地备份清单生成与文件校验，不执行停机、数据库导出或 Docker 操作；调用方须先检查源状态和转储可读性。
- archive.py：受限归档检查与安全恢复，恢复使用私有快照，不覆盖目标目录已有文件。
- metadata.sql：只读版本和计数基准查询，不输出业务正文或凭据。
- compose.restore-001.yml：仅适用于 backup-001 的固定镜像恢复覆盖配置，不是通用恢复命令。

原演练入口：http://127.0.0.1:3100；独立恢复入口：http://127.0.0.1:3101。
恢复项目必须为 devdocs-restore-001，使用独立 .env.restore-001；严禁把恢复覆盖配置套用到源项目。
目标恢复卷现在已有数据，不能重复执行恢复。后续演练必须选全新编号并重新检查配置、项目、卷、端口和版本。
恢复库在核对基准后增加了浏览器测试专用账号和资料，因此测试后的总计数不再等于备份时计数。
恢复报告位于 backups/backup-001/restore-001-report.json，原 manifest.json 保持不变。
通用生命周期/升级/自动备份恢复 CLI 尚未交付，不应把本次明确限定的实际操作当作通用自动化工具。

默认只开放 127.0.0.1:3100；数据库和后端不发布宿主机端口。
实际凭据文件 .env.rehearsal 不提交、不展示。当前 HTTP 演练不具备公网 HTTPS 安全边界。
不要执行 down -v 或卷清理来排障；首次初始化 SQL 不会在已有卷上自动重新执行。
