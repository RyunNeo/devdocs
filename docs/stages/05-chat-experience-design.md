# 会话体验模块设计：键盘发送、校验后展示、历史恢复

日期：2026-10-15。状态：设计及计划均已通过，代码已实现，待用户完整链路验收。

## 1. 用户目标

让知识库问答可以持续使用：回车发送、Shift+Enter 换行；不再先展示推测草稿再撤回；
会话可以从页面找到、恢复和继续提问，不需要手动保存带 conversation 参数的地址。
用户已选择“不额外开启深度思考”。本模块作为一条完整流程交付，不逐个小功能要求验收。

## 2. 现状与取舍

当前会话和消息已经保存在数据库，但没有列表入口，进入不带参数的问答页不会恢复最近会话。
当前 token 在校验前发往浏览器，因此可能先展示推测内容，结束时又变成依据不足。

采用服务端暂存本轮生成结果，校验并保存成功后才发布正文；沿用 SSE 传输状态和最终结果。
这比仅在前端隐藏草稿更明确：未校验正文不离开后端，刷新历史也不会看到失败草稿。
不增加第二次审核模型调用，不启用思考模式；隐藏草稿不等于节省已产生的 token。
是否能减少生成量取决于检索是否足够可靠，本模块不承诺仅凭阈值完全识别无关问题。

## 3. 输入行为

- Enter：提交去首尾空白后的问题。
- Shift+Enter：原生换行。
- 中文等输入法组合输入期间，包括 isComposing 和兼容的 229 按键状态，不触发提交。
- 忽略长按重复提交，空问题、禁用状态和已有请求不提交；点击发送按钮行为一致。
- 保留当前 2000 字符上限；不在页面增加键盘快捷键说明。

## 4. 校验后展示

保持单次问题 Embedding 和单次回答生成的现有路径，空库仍不调用模型。
收到 meta 后显示用户问题和处理状态，不显示 assistant 草稿。
新增 status 事件，phase 为 retrieving / generating / validating，分别显示“正在检索”“正在生成”“正在校验”。
这些是处理状态，不是模型思维过程，也不把 reasoning_content 展示或保存。

生成 token 在服务端内存中累积，仍受绝对超时、响应大小、取消和单会话租约保护。
生成成功后依次完成依据不足归一化、引用编号校验、来源状态刷新和数据库保存。
仅在上述流程成功后，发送已验证正文 token 分片、citations 和 done。
这些分片只为控制帧大小，立即发送，不人工延迟打字，也不二次请求模型。
引用编号校验仍不能证明每句话被原文支持，质量验收需要对照知识库原文。

- 固定依据不足：仅发布中文提示，引用为空，不暴露内部标记和前面的推测内容。
- 引用非法/模型失败/截断：error 结束，显示失败原因，不展示未校验正文。
- 停止：显示“已停止”，新失败/取消记录的 assistant content 为空，不保存生成草稿。
- 旧 failed/cancelled 消息原数据不改写；读取和界面不再返回/展示其中的未校验 assistant 正文及引用。
- 旧 completed 答案不自动重新验证或改写，需要新提问验证新逻辑。
- 服务端已保存但前端断线：从历史读取 completed 结果，不自动重试付费请求。

## 5. 标签与会话恢复

知识库内部提供“文档 / 问答 / 历史会话”导航标签，保留现有文档及问答地址，新增历史页。
标签采用普通页面导航，标明当前页面；移动端能完整显示或横向滚动，不溢出屏幕。

历史页按最近更新时间降序列出非空会话，每页 20 条：标题、最近问题摘要、更新时间和最新回答状态。
标题从第一条用户问题截取最多 40 字符，摘要最多 80 字符；不额外调用模型生成标题。
历史页不展示完整正文和引用快照，防止列表加载过重；没有消息的创建记录不进入列表。
点击会话进入原 conversation_id，恢复该会话消息、引用和追问上下文。

进入不带 conversation 参数的问答页时，查询该知识库最近一条非空会话并恢复，URL 同步保存其 ID。
无历史时显示新会话空态，首次提交才创建记录，不因进入页面创建空记录。
“新会话”清空当前消息并进入显式 new=1 地址，避免刷新后误恢复旧会话；
首次提交创建完成后将 new=1 替换为真实 conversation 参数。
明确指定不存在/非所属会话时显示不可访问，不静默跳到另一个会话。

生成中禁用页面内会话切换和新建，保留停止按钮；普通浏览器离开/刷新按现有中断规则处理。
生成完成后可切换并继续原会话，不同会话的草稿和请求不得串线。

## 6. 后端接口

- GET /knowledge-bases/{id}/conversations：limit 默认20、范围1–100，offset>=0，items/total/limit/offset。
  items 含 id、knowledge_base_id、title、last_question、latest_status、created_at、updated_at，不含正文。
- 沿用 POST /knowledge-bases/{id}/conversations 和 GET /conversations/{id}。
- GET /conversations/{id} 增加可选 before_sequence>=1、limit 默认40/范围1–100，
  消息按 sequence 升序返回，has_older 表示是否还有更早记录，前端提供加载更早消息入口。
- 会话读取的失败/取消 assistant 消息正文及引用为空；用户问题不删改。
- 所有列表、详情及更早消息均先做所属用户/知识库校验；401/404 与当前契约一致。

复用现有 conversations/messages 表，标题与摘要由已有消息查询派生，预计不需要新迁移。
未新增历史会话重命名、删除、搜索、跨知识库会话合并；这些不是本轮目标。

- 更新第四阶段相关测试中“草稿实时可见”的断言，不把它继续作为目标；原 SSE 帧限制不放宽。
- 新事件增加后前后端需同时生效，测试后统一指导重启，不让新后端长期配旧前端。

## 8. 验收与风险

- 单元/浏览器：Enter 一次提交、Shift+Enter 换行、输入法确认不误发、长按不重复发送。
- API/浏览器：延迟假模型先发送错误草稿时，完成校验前页面和应用 token 事件均无正文；
  只有最终中文拒答出现，原始标记不泄露到用户可见消息。
- API：非法引用、断流、超时、停止的正文为空；正常完成后先保存再发布。
- 历史：原有记录出现，返回问答恢复最近，显式新会话刷新仍为空，点击历史继续同一 ID。
- 分页/权限：超过40条加载更早消息，历史列表分页，跨账号/跨知识库不可访问。
- 竞态：停止/保存竞争、切换旧请求迟到、刷新后 completed 恢复均不串线、不自动重试。
- 截图：桌面与390px移动端导航、历史列表、输入区不重叠、不溢出。
- 回归：已有认证、上传、索引、检索和引用仍通过；测试用假模型及隔离数据库，不发真实付费请求。

等待完整生成会增加首次正文可见的等待，因此必须提供真实阶段状态和停止能力。
本模块改善展示与会话可达性，不自动弥补错误上传资料、未命中检索或模型事实错误。
