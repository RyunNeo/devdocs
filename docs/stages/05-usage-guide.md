# 个人用量、日志与每日配额验收

## 先执行迁移，再重启后端

本模块新增迁移 `0007_usage_events_counters`。助手只迁移了隔离测试库，没有修改你的真实数据库。
保持 PostgreSQL 已启动，在项目的 `apps/api` 目录执行：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
```

预期显示 `0007_usage_events_counters (head)`。迁移新增操作记录和每日计数，不改写旧会话；仍建议先按日常方式备份数据库。
如果旧后端仍在运行，先在它所在终端停止，再启动：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000 --no-access-log
```

`--no-access-log` 关闭 Uvicorn 原始 URL 访问日志。应用会输出只含固定路由模板、请求编号、状态和耗时的日志，不记录问题、回答、文件名或密钥。
助手保留了原服务，没有自动重启它去使用尚未由你迁移的数据库。前端仍为 `http://127.0.0.1:3001`，完成以上操作后刷新。

## 配额配置

默认每账号每天问答 50 次、文档索引 20 次。无需新增密钥，不配置以下两项也能使用默认值。
需要调整时，在后端实际读取的 `apps/api/.env` 中手动增加或修改非敏感配置：

```dotenv
DAILY_CHAT_LIMIT=50
DAILY_INDEX_LIMIT=20
```

两项必须是正整数，更改后重启后端。不要修改模型密钥，也不要把密钥发到聊天中。
调低额度后，已用次数不会减少；剩余次数最小为 0。

## 统计规则

- 每天 UTC+08:00 的 00:00 重置，以任务受理时间归属当天，跨日完成不再扣第二天。
- 每个有效受理问答占一次，包括空库的本地无依据回复。每份实际开始建立或重建索引的文档占一次。
- 索引可直接复用时不重复扣次；上传、删除、读取历史和用量不扣次。
- 被受理后失败、取消或断连也不返还次数。重复请求或受理前的权限、参数、配置错误不会多扣。
- 删除文档、会话或知识库不会清除已用次数和已有操作记录；重启后端也不会重置。
- 次数是本站逻辑任务数量，不是供应商请求次数或账单金额。
- 只展示可靠的已知 Token。某阶段缺少 usage 会显示“未知”或“不完整”；“未调用”表示该操作没有记录供应商调用尝试。
- 本模块上线前的旧消息不会回填为完整账本。页面“统计起始”是当前账号第一条新记录的时间。

## 一次完成的验收链路

1. 登录后打开侧栏“用量”，检查今日配额和无记录状态。
2. 上传新文档并建立索引，再刷新“用量”，应有索引记录，剩余索引次数减一。
3. 对同一文档再次建立索引：若后端确认能复用，余额不再减少。
4. 在知识库提问，检查问答记录、结果、耗时、模型和请求编号。缺失 Token 不应误标为完整的 0。
5. 尝试筛选任务类型与结果，检查分页、刷新和手机宽度。
6. 可临时降低某项配额并重启，验证达到上限时出现当天重置时间，未提交问题仍保留，批量索引停止后续任务。验收后恢复配置并重启。
7. 删除测试文档或知识库：操作记录与已用次数仍在；另一个账号不应看到这些记录。

长时间未正常结束的记录，会在查看用量时按问答/索引上限加宽限期标记为“已中断”。它不证明供应商零消耗，也不会返还配额。

## 故障定位与代码阅读

请求返回 `X-Request-ID`，用量表格也保存对应请求编号，可用来查找本机结构化日志。
超额为 HTTP 429，`code=daily_quota_exceeded`；它与供应商额度、供应商限流不是同一个概念。

- `app/models/usage.py`：新增的两个表。
- `app/services/usage_service.py`：原子占额、终态、过期和个人汇总。
- `app/core/usage_context.py`：阶段耗时与供应商用量采集。
- `app/core/logging.py`：脱敏日志和服务端请求编号。
- `app/api/routes_usage.py`：`GET /usage/summary`、`GET /usage/events`。
- `apps/web/components/usage/usage-workspace.tsx`：个人用量页面。

本模块不提供收费、充值、金额估算或管理员额度编辑页面。
