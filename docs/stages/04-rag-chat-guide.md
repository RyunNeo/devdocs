# 第四阶段：检索与流式问答使用指南

代码已实现，自动化使用假模型验证；真实模型权限、回答质量和费用由你的验收确认。
第三阶段已按你的反馈验收通过。本阶段不需要重新索引已有的有效文档。

## 1. 先升级数据库

在项目根目录打开终端，执行：

```powershell
cd apps/api
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
```

预期最后显示 `0006_conversations_messages (head)`。
迁移只增加 conversations/messages，不删除现有知识库、文档和向量。
后端更新后的 ready 检查会要求这两张新表，所以先迁移再重启。
降级到 0005 会删除本阶段的会话消息；不要在已有真实会话后随意降级。

## 2. 配置

实际配置仍在 `apps/api/.env`，不是 `.env.example`。
你已经配置过的 `SILICONFLOW_API_KEY` 可以继续使用，不需要把密钥发给助手。
回答模型有默认值，下面这些非敏感配置可按需要加入 `.env`，不加入也使用相同默认值：

```dotenv
CHAT_MODEL=deepseek-ai/DeepSeek-V4-Flash
CHAT_MAX_TOKENS=1024
CHAT_TIMEOUT_SECONDS=90
RETRIEVAL_TOP_K=5
RETRIEVAL_MIN_SIMILARITY=0.35
```

Embedding 仍为 BAAI/bge-m3。两个模型的职责不同：前者生成答案，后者匹配文档。
聊天请求关闭模型思考模式，不展示或保存 reasoning_content。
接口和参数依据硅基流动官方文档：
https://docs.siliconflow.cn/docs/api/chat-completions-post
模型 ID 被文档列出不等于你的账号有权限，真实点击发送时才会验证。

## 3. 启动与入口

迁移完成后，请告知助手 `0006_conversations_messages (head)`，由助手核对并重启已有后端。
自行启动时先停止自己原来的后端终端，避免同时占用 8000：

```powershell
cd apps/api
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

前端继续使用 http://127.0.0.1:3001。
进入知识库详情，点击“知识库问答”，不需要创建新的账号或重新上传资料。
首次发送创建会话，地址会增加 conversation 参数；刷新这个地址可恢复已保存消息。
会话历史入口现已提供，见 `05-chat-experience-guide.md`；进入问答会默认恢复最近会话。

## 4. 一次性验收整条链路

使用不含敏感信息的小型 Markdown/TXT/文本 PDF，确认文档“可检索”后提问。

| 操作 | 预期 |
| --- | --- |
| 问一个文档明确包含的问题 | 显示处理阶段，校验保存后展示正文，“回答完成”且来源编号有效 |
| 点击引用编号 | 显示文件名、正文片段、Markdown 标题或 PDF 页码 |
| 同一会话追问“再解释一下它的作用” | 结合最近主题检索，不引用别的知识库 |
| 问文档完全无关的问题 | 明确说明依据不足；不是保证任何无关问题都能靠阈值识别 |
| 空库或未完成索引的库提问 | 返回依据不足，不调用 Embedding/回答模型 |
| 生成中点击停止 | 当前回答“已停止”，不展示或保存未校验草稿，允许再次提问 |
| 刷新地址 | 已保存的问题/回答/引用恢复，不自动重复生成 |
| 新会话 | 页面清空并去掉 conversation 参数，不删除旧会话 |
| 生成后删除引用文档，再刷新 | 引用显示“原文已删除”，正文是回答时快照 |
| 两个账号访问同一会话地址 | 非所属会话不可访问，不泄露正文 |

建议一次准备 5 个有据问题、3 个无关问题、2 组追问。
记录：答案是否被引用原文支持、来源定位是否正确、首段出现时间、总等待时间。
编号校验只保证编号对应检索来源，不能自动证明每句话真实。

如果回答偏离预期，先核对文档列表和引用原文，确认上传内容而非仅知识库名称符合业务主题。
项目 README 的工程目录不能代替完整的产品定位或业务规则文档。
模型混合输出推测正文和依据不足标记时，最终统一转换为中文依据不足提示，不保存为有引用的成功事实答案。
更新提示词不会改写已有会话；调整资料后建议新建会话测试，避免旧主题干扰检索。

## 5. 流程对应的代码

- `app/rag/retriever.py`：完成索引/模型维度/所属过滤、pgvector 余弦排序。
- `app/rag/prompts.py`：最近已完成问答和不可信文档边界。
- `app/rag/chat_model.py`：供应商 SSE 解析、超时、拒绝截断结果。
- `app/services/chat_service.py`：单会话租约、短事务、取消、先保存后 done。
- `apps/web/lib/stream.ts`：中文增量解码、完整帧、缺终态检测。
- `apps/web/components/chat`：页面、输入、消息和引用弹窗。

本阶段值得理解的是：HTTP 200 只说明流建立了，不说明回答成功。
只有收到应用 done，且服务端保存成功，页面才显示“回答完成”。

## 6. 常见状态

| 情况 | 处理 |
| --- | --- |
| 缺少新表/数据库暂不可用 | 确认 0006 head、数据库运行，再重启 |
| 请先配置 SILICONFLOW_API_KEY | 检查实际 .env、重启；不要贴密钥 |
| 模型服务拒绝请求 | 检查平台模型权限、额度和密钥，错误不会回显平台原文 |
| 引用校验失败 | 不展示草稿，显示失败状态；核对资料后再提问 |
| 回答超时/连接中断 | 刷新确认服务端终态；不要无条件重复点击以免重复计费 |
| 当前会话正在回答 | 停止或等待；崩溃遗留的租约 180 秒后在读取/发送时恢复 |
| 回答任务较多 | 本地单进程已有 2 个任务，稍后再试 |

## 7. 成本和当前边界

每轮最多一次问题 Embedding 和一次回答调用，无自动模型重试。
正常完成答案不会在 done 中整篇重复发送；仅固定拒答可能用 content 替换草稿。
SSE 使用 no-transform 防止代理压缩缓冲；部署时同样需要关闭流式代理缓冲。
检索资料正文、标题和文件名的序列化总预算 12000 UTF-8 字节；过长标题会截短。
初始相似度 0.35 不是置信度，需要你的问题样本校准。
连续追问只保留最近 3 对成功问答，最多 6000 字符，不保证复杂指代全部理解。
停止会尽力关闭连接，已消耗的供应商计算仍可能计费。
原文删除后会话保留引用快照；删除知识库会删除其全部会话与快照。
生成中进程崩溃不保留草稿；断线后可能存在“服务端成功但浏览器未确认”，通过历史恢复。
全局并发限制适合当前单进程学习环境，不是生产级分布式限流。
正式上线之前还需要后续的日志用量、质量评测和部署安全检查。
