# 第六阶段模块一：RAG 质量评测闭环

状态：设计及实施计划已由用户确认，按计划在当前会话实现。第五阶段已由用户确认验收完成。

## 1. 目标与约束

帮助开发者判断回答是否忠于上传资料，并在后续调整模型、提示词和分块时进行可重复对比。
用户同意先采用独立测试资料；助手编写代码和自动测试，用户参与实际运行和答案评分。

本轮交付一条完整流程：校验资料与问题集 → 创建专用测试知识库 → 上传与索引 → 顺序提问 → 保存结果 → 人工评分 → 汇总报告。
不包含生产部署、评测管理页面、学习卡片、Agent 或模型自动裁判。
不修改现有业务接口，不增加数据库表或迁移，不自动访问真实模型或修改密钥。

## 2. 方案选择

- 采用独立 Python 命令行工具，通过现有 HTTP API 执行评测：覆盖真实业务链路，结果便于复现，复用现有 httpx 依赖。
- 暂不直接调用内部 RAG 服务：这种方式方便拿到候选片段，但容易绕过认证、配额和消息持久化，与用户实际体验不一致。
- 暂不开发网页评测中心或模型裁判：增加页面、任务调度、调用成本和评分可靠性问题，超出本轮范围。

## 3. 资料与问题集

在 `evals/fixtures` 编写 4 份原创中文技术资料，围绕一个明确标注为虚构的开发项目。
包含产品定位、组件与状态规范、API/权限规范、发布与排障规则；规则使用便于核对的具体事实。
这些是测试资料，不是当前 DevDocs AI 真实功能说明，也不依赖实时框架文档。

在 `evals/datasets` 维护版本化的 24 条问题：

| 类型 | 数量 | 检查目标 |
| --- | --- | --- |
| 单文档事实 | 8 | 数字、名称和约束是否准确 |
| 跨文档综合 | 4 | 是否组合必要来源，避免张冠李戴 |
| 应拒答问题 | 4 | 资料没有答案时是否承认证据不足 |
| 多轮追问 | 6 | 组成 3 组两轮对话，验证上下文指代 |
| 注入与相似事实干扰 | 2 | 不服从文档中的恶意指令，不混淆规则 |

每条包含稳定 ID、类别、问题、期望行为、参考答案、必需事实、禁止事实、期望来源文件与证据原文。
多轮问题额外包含会话分组和顺序。参考答案与评分规则仅供本地评分，不随问题发送给模型。
评测前校验 ID 唯一、文件存在、证据原文确实在资料中、多轮顺序与引用关系有效。
证据文本不能依赖易随分块变化的 chunk 序号。

## 4. 工具与操作流程

建议入口为 `evals/run.py`，由后端虚拟环境运行，提供以下命令职责；精确参数在实施计划中确定：

1. `validate`：离线校验资料和数据集，不连接后端或供应商。
2. `prepare`：用户显式同意真实调用后，登录并创建带唯一运行标识的测试知识库，顺序上传 4 份资料并建立索引。
3. `run`：读取本次准备清单，在指定测试知识库中按顺序执行问题，保存会话、答案、引用与执行状态。
4. `report`：读取本地结果和人工评分，离线生成 Markdown 报告。

首次使用建议新建一个测试账号，但工具不自动注册账号。
密码由交互式隐藏输入提供，不接受明文命令行密码、不写入文件；登录 Cookie 仅存内存。
工具通过后端基础地址调用 API，不接收模型密钥，调用前显示地址、资料版本和计划任务数。
默认仅允许本机 HTTP；远程必须 HTTPS 且显式启用，不向任意重定向地址转发凭据。

准备与运行使用同一份本地清单，校验资料哈希与知识库文档清单，避免误用普通知识库或悄悄混入额外资料。
清单保留专用知识库 ID、文档映射及哈希、数据集版本和哈希、已知配置快照。
不可通过接口取得的模型或检索参数标为未知，允许用户补充非敏感备注，不能伪造运行配置。
每条独立题创建新会话；同一多轮分组复用一个会话，前一轮失败时后续轮次标为阻塞。
正常完成一轮准备最多建立 4 份索引，完整问答运行最多受理 24 次，均消耗测试账号现有额度。
开始前检查剩余额度；额度不足时默认不执行整批，提示用户选择较小子集或另一天运行。

## 5. SSE、失败与重跑

按现有 SSE 协议读取状态、最终答案和引用，并用会话详情核对持久化结果。
必须正确处理分包、UTF-8、多行 data、心跳及连接提前关闭，不能假设一块网络数据就是一个事件。
使用有界连接与读取超时，完整消费响应，不收到首个文本就断开，避免把任务误取消。
只把持久化的已完成消息作为成功结果，超时、失败和格式错误另列，不计作拒答成功。
中断或状态不明确时记录会话 ID 与请求 UUID，不自动再次提交，以免重复扣额。
可只读重新查询历史以确认原任务结果；仍不明确则保留 unknown。
429、401、后端不可达及索引失败时停止后续任务并保留已有结果，不自动重试收费请求。
再次跑题必须显式选择，产生新的运行目录；不静默拼接不同运行结果或覆盖历史。
不自动删除知识库、文档或会话；用户可在现有页面清理专用测试数据，删除也不会返还配额。

## 6. 记录与评分

每次运行独立保存清单、逐题 JSONL、人工评分 CSV 和 Markdown 报告。
每完成一题立即落盘；结果仅包含原创测试资料及响应，不保存密码、Cookie、密钥或完整请求头。
输出目录为 `evals/results/<run-id>`，运行 ID 只能是安全目录名，已有运行禁止覆盖。

自动指标明确标注其含义：

- 执行完成率：已完成问答数 / 实际尝试问答数，未尝试和阻塞单列。
- 期望来源覆盖：在需要回答且已完成的题目中，实际引用命中的期望文档数 / 期望文档数；同时报告逐题全覆盖比例。
- 引用结构检查：引用编号与条目能否对应，不等价于事实得到支持。
- 必需事实与禁止事实匹配：只做辅助提示，关键词匹配不判定语义正确。
- 客户端完整响应耗时：从提交到完整接收，统计样本数、中位数和 P95；不命名为模型首 Token 延迟。
- 已知 Token：仅使用响应实际提供的 usage，缺失显示未知；不根据文本长度估算费用，不用账号级总量差冒充单题消耗。

当前公共接口没有返回完整检索候选，因此不报告 Recall@K、MRR 或实际未曝光的检索分数。

人工评分 CSV 每题提供参考事实和结果位置，评分项为：

- 答案正确性：0 错误、1 部分正确、2 正确。
- 引用支持性：0 不支持、1 部分支持、2 充分支持；应拒答题可填不适用。
- 应拒答题：通过 / 未通过，人工判断是否确实没有编造答案。
- 多轮一致性：通过 / 未通过；非多轮题不适用。
- 备注：错误事实、遗漏、无依据扩展等。

未评分保留空值，绝不视为 0 分或通过。报告同时列出已评分数量与分母。
错误编号、重复评分、非法分值和不适用字段填写冲突应报错，不静默忽略。
人工答案通过线为正确性 2 分且引用支持性 2 分；应拒答题以人工拒答判定为准。
首轮目标为建立真实基线，不承诺某个准确率。建议试用前达到已评分全量题 80% 通过，且应拒答和注入场景无严重编造；未满足则先定位问题。

## 7. 实现边界与目录

工具按职责拆为数据集校验、HTTP/SSE 客户端、运行编排、结果与报告模块，避免一个巨大脚本。
复用后端虚拟环境与现有依赖，不新增 LLM 框架、外部评测平台或前端入口。
数据集及原创资料可纳入版本管理，运行产物、评分和本地清单应排除提交。
补充 `docs/stages/06-evaluation-guide.md`，包括准备、成本提示、评分示例及常见失败排查。
同步 README 和阶段状态，明确第五阶段已验收、第六阶段评测进行中、部署未开始。
当前工作区无 Git 仓库，不为交付文档擅自初始化仓库或创建提交。

## 8. 验证与验收

自动测试使用假 HTTP/SSE 响应或隔离测试服务，不访问真实供应商：

- 校验正常及损坏数据集，覆盖路径越界、证据缺失、重复 ID、多轮顺序错误。
- 覆盖登录失败、上传/索引失败、200 但索引业务失败、429、断流、消息未持久化和状态不明。
- 覆盖 SSE 任意分包、心跳和中文字符边界。
- 验证会话隔离、多轮复用、失败依赖阻塞，以及收费请求不自动重试。
- 验证已完成题及时保存、已有结果不覆盖、未评分不算通过、Token 缺失为未知。
- 校验报告分母、来源覆盖计算、人工评分导入及敏感信息不落盘。
- 运行后端现有相关回归测试；本轮无前端修改则不要求重新跑全部浏览器用例。

用户验收：先完成无费用离线校验，再显式执行 3 题小批试跑并填写评分，确认流程后运行剩余题目；拿到可追踪来源、答案和评分的报告。
真实模型结果由用户实际运行产生，助手不会以模拟结果宣称回答质量已经达标。
