# 第六阶段模块二：本地生产环境演练

状态：用户已同意容器化演练方向，并请求进入实施计划；设计已作为计划依据，尚不开始实现或启动服务。

## 1. 目标与范围

用户目前没有服务器和域名，希望继续参与项目配置学习。助手负责代码、容器配置、脚本与测试，用户参与本地配置和完整流程验收。
本模块在 Windows + Docker Desktop 的 Linux 容器环境中运行生产构建，验证启动、独立存储、迁移、重启、备份和隔离恢复。
评测模块按用户确认记为已验收；这不等于所有模型、所有题目均已达到质量阈值。

本轮不购买资源、不公开服务、不配置真实域名或证书、不迁移开发数据、不实现计费与多节点扩容。
不会把本机 HTTP 演练宣称为已经上线或完整满足公网生产安全要求。

## 2. 方案与系统边界

选择独立 Docker Compose 栈，而非直接在 Windows 启动生产进程，便于验证未来 Linux 环境与数据持久化。
保留根目录现有 docker-compose.yml，不将演练配置合并到开发配置中。
默认 Compose 项目名 `devdocs-rehearsal`，服务为 web、api、postgres，另设一次性 migrate 和存储初始化任务。
恢复项目名使用独立的 `devdocs-restore-<安全运行编号>`，不能指定开发项目或原演练项目为恢复目标。
所有镜像与辅助服务配置明确限定用途，容器不挂载 Docker socket，也不挂载项目源码到运行容器。

数据流：浏览器 → `http://127.0.0.1:3100` → Next.js → 内网 FastAPI → PostgreSQL 与上传存储卷。
web 为唯一对宿主机发布端口的应用服务，绑定 127.0.0.1；api 和 postgres 不发布宿主机端口。
恢复环境默认使用 3101；启动前发现端口占用应明确报错，不停止占用者。
服务内部监听 0.0.0.0 是容器互通所需，不代表允许宿主机公网访问。

## 3. 镜像与进程

### 前端

使用现有 Node 22 基线与 package-lock.json，通过 npm ci 安装锁定依赖，使用 Next.js 生产构建。
采用 standalone 运行产物，正确包含 monorepo 追踪范围、static 和 public（如存在）资源。
生产镜像不复制 node_modules 开发树、测试结果、evals/results、work、.env 或本机虚拟环境。
容器使用非 root 用户运行，不启用 next dev，保留现有开发启动方式不变。

构建期将服务端 API_BASE_URL 固定为 `http://api:8000`；现有 rewrites 是构建配置，不能声称任意运行时改值就生效。
恢复栈内 api 仍使用同一服务名，因此可以复用镜像。修改后端服务地址时需要重新构建前端。
不使用 NEXT_PUBLIC_* 暴露数据库地址或模型凭据。

### 后端

采用 Python 3.14 Linux 基线，从现有 requirements.lock.txt 安装锁定依赖；构建验证 Linux 兼容性，不静默更新依赖版本。
复制业务代码和 Alembic 文件，运行单 Uvicorn worker，关闭 reload 和原始 access log。
保持当前 ChatRuntime 进程内限制语义，不在未验证前启用多 worker。
业务进程以非 root 用户运行；上传卷权限由显式一次性初始化任务设置，仅作用于本栈上传卷。
上传路径固定为容器 `/data/uploads`，源文档不作为静态资源公开。

### 数据库

使用项目已有 pgvector/pgvector:pg16 基线，初始化安装 vector 扩展。
演练使用独立账号、数据库和命名数据卷，不使用开发账号默认密码，不接入 127.0.0.1:5432。
现有数据库模型和业务迁移不变；演练库通过现有迁移升级至当前 head。
镜像基线在实际构建时记录可获得的镜像标识，报告其可复现程度，不把浮动 tag 称为不可变版本。

## 4. 配置与凭据

配置示例位于 infra/deploy，只提供占位值与非敏感默认项。
实际配置保存到被忽略的专用文件 `infra/deploy/.env.rehearsal`，不覆盖 apps/api/.env 或 .env.example。
初始化工具可为新演练栈生成 URL 安全的随机数据库密码并直接写入该文件，不打印密码，也不覆盖已有配置。
用户无需把凭据发到聊天；助手不读取现有开发密钥，也不自动复制它到演练配置。
容器构建上下文通过 .dockerignore 排除所有真实配置、上传文件、运行产物和工作目录；凭据不得成为 Docker build ARG 或镜像层内容。
环境检查与脚本不能打印完整 docker compose config、docker inspect 环境变量或连接字符串。

基础验收不配置模型密钥：可完成注册、登录、知识库、上传解析、历史及空库无依据回复。
真实索引与有依据问答由用户另行把密钥填入演练配置后显式执行；指南说明会产生费用，助手验证默认使用假服务或无模型流程。
允许的 Origin 精确配置为当前演练页面地址；恢复栈对应新端口。
演练 Cookie 使用独立名称，恢复环境再使用另一名称，避免同机不同端口之间覆盖开发登录。
由于本轮为本机 HTTP，COOKIE_SECURE=false 仅用于环回演练；公网部署前必须补齐 HTTPS、Secure Cookie、正式 Origin 与网络访问控制。
Docker 管理权限本身可以读取容器环境，不能声称容器环境变量是对本机管理员保密的密钥保险箱。

## 5. 启动、迁移与停止

提供适合 PowerShell 的统一操作入口与中文指南，具体命令在实施计划中确定。
首次流程：检查 Docker/Linux 容器模式与端口 → 初始化演练配置 → 构建 → 启动数据库 → 执行卷初始化与一次性迁移 → 启动 api/web → 就绪检查。
迁移任务只在用户执行演练启动/迁移命令时运行，不在每个 API 请求或每个 worker 启动时执行。
迁移失败阻止后续应用启动，并给出无凭据的错误摘要；不自动 downgrade 或删除数据卷。
新增镜像更新已有演练库前需先备份，不能将重启命令当作自动安全升级承诺。

api 健康检查使用现有 `/health/ready`，核对数据库、pgvector 与业务表；web 检查可服务的实际页面/路由。
Compose 启动依赖与脚本轮询均设置超时，不能仅以容器进程存在就宣称应用可用。
检查结果显示服务状态、入口 URL 与非敏感故障编号；日志继续采用现有脱敏应用日志。
停止仅停止本栈服务，保留命名数据卷；默认流程不包含 down -v、volume prune 或任何开发目录删除。
操作失败保留已有进度，不能自动清空重建来掩盖故障。

## 6. 成对备份

备份同时包含数据库转储和上传原文件；仅有数据库不算可恢复备份。
先记录本栈原有运行状态，停止 web/api，确认写入入口和后台任务不再运行，再进行备份；postgres 保持运行。
备份期间不允许迁移或其他工具绕过该入口写入数据，指南明确这是停机备份而非在线一致性快照。
停止超时或备份任一步失败均返回失败，不生成“备份完成”标记。
完成或失败后的恢复启动只针对操作前运行的服务，不能擅自启动原本已停止的应用。

使用 pg_dump 自定义格式与上传卷 tar 归档，输出到本栈专用备份目录下的全新运行子目录。
Windows PowerShell 不使用文本管道或 `>` 转发二进制转储：先在容器内生成文件，再通过 Docker 文件复制保留字节。
归档完成后核对可读性、文件大小与 SHA-256，最后原子写入完整备份清单。
清单含格式版本、创建时间、源栈、迁移版本、文件哈希及可获取的镜像标识，不含密码、密钥、Cookie 或完整环境变量。
不完整备份保留供排障，但不能被恢复命令当作成功备份。
数据库转储包含用户资料、密码哈希与会话记录，上传归档可能含私有资料；必须视为敏感数据，仅本机保存且不提交 Git，不自动上传第三方。
本模块不提供加密备份承诺，指南要求离机保存前由用户选择适当加密方式。

## 7. 隔离恢复演练

仅接受格式、完整标记和校验和均有效的备份；归档路径只允许预期的相对文件条目，拒绝绝对路径、上级目录穿越和符号/硬链接。
恢复到全新的恢复项目、数据库与上传卷，不覆盖原演练栈，不连接开发库，不自动删除任何已有恢复栈。
目标已存在时停止并要求新编号，不能用 --force 绕过该限制。
固定恢复所需的 PostgreSQL/pgvector 主版本兼容边界，版本不兼容应阻止操作。
恢复配置生成新的数据库凭据和 Cookie 名，不从备份自动恢复模型密钥。
数据库与上传均恢复完成后才启动应用；核对已记录的 Alembic 版本与当前应用 head，不隐式升级来源未知的旧备份。
恢复后清理恢复库中的旧登录会话，要求重新登录；不改动源库会话。
对比关键表记录数量和上传文件数量/哈希，检查就绪状态，并由用户登录确认知识库、文档、历史与引用可读。
业务恢复验证默认不调用模型；有原有已完成索引时可以检查状态和历史，不通过重新付费索引证明恢复成功。
恢复环境的存在不等于备份永远有效，后续变更应重新演练。

## 8. 代码与交付位置

- infra/deploy：web/api Dockerfile、独立 Compose、配置样例和部署操作脚本。
- infra/deploy 的辅助脚本按配置/栈操作与备份恢复职责拆分，避免一个巨大脚本。
- docs/stages/06-local-production-guide.md：Windows 配置、启动、验收、备份、恢复和排障。
- 新增针对配置、隔离规则与备份归档的自动测试；复用现有浏览器测试验证生产构建基础链路。
- .dockerignore、.gitignore：排除真实凭据、备份和运行产物。
- apps/web/next.config.ts：只调整生产构建所需配置，按已安装 Next.js 文档验证，不破坏现有开发入口。
- README 和阶段记录：更新评测模块验收状态、演练范围及尚未完成的公网部署项。

当前目录没有 Git 仓库，保持就地协作，不初始化仓库或创建无依据的提交。

## 9. 验证与验收

自动验证包括：配置缺失与已有文件保护、限定项目名与端口、无开发卷引用、镜像无敏感文件、迁移失败阻断、日志不暴露凭据。
备份恢复测试包括：哈希不匹配、不完整归档、路径越界/链接条目、既有目标保护、失败后原服务状态恢复，以及二进制转储无文本损坏。
真实 Docker 演练使用本模块全新数据库，不对开发库运行迁移、恢复或清理。
生产构建验收：注册登录、创建知识库、上传解析、历史/用量页面、空库问答、退出和账号隔离；不自动使用真实供应商。
使用同一生产入口验证 SSE 可用；有依据回复通过隔离假服务验证完整协议，不以空库回复替代全部 SSE 验收。
重启服务后测试数据和原文件仍在；完成一次成对备份及全新恢复栈核对，保留可审阅的验证记录。
现有单元、集成及受影响浏览器测试通过；未实际完成 Docker 构建/恢复时必须明确报告限制，不能仅凭配置文件宣称演练成功。

用户验收以指南完整走通本机环境与恢复检查为准。此模块验收后，再讨论服务器、域名、HTTPS、远程备份及真实开发者试用。
