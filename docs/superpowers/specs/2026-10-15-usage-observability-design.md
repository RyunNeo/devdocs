# 日志、个人用量与每日配额设计

状态：用户已确认设计。下一步审阅实施计划，再编写业务代码。

## 1. 目标与已确认规则

面向当前个人开发、学习阶段，把一次问答或索引的受理、耗时、用量和错误关联起来，并提供个人用量页面。
用户已授权采用推荐规则：达到每日配额后阻止新任务，已经受理的任务正常完成。
保留现有批量操作、校验后展示、打字机效果和会话历史。

本模块不实现收费账单、支付、团队管理、可视化管理员后台、分布式任务队列或生产部署。
次数配额是调用保护，不保证供应商账单金额或供应商请求次数的上限。

## 2. 方案选择

- 仅从 messages 汇总：改动少，但无法覆盖索引、被删除的会话、途中失败和并发配额，不采用。
- 独立操作记录加数据库每日计数：覆盖现有两条链路，支持多进程下原子占额，本模块采用。
- 外接观测和计费平台：引入额外账户、运维及数据外发，本模块不接入。

## 3. 次数配额

默认后端配置：`DAILY_CHAT_LIMIT=50`、`DAILY_INDEX_LIMIT=20`，均为每账号每日的逻辑任务次数，取值为正整数。
通过配置调大或调小，不在前端提供修改入口，也不把配置写入含真实密钥的文件。
现有环境文件未设置时使用默认值；指南只讲解新增的非敏感配置。

- 一次被受理的问答占 1 次问答配额，包括其中的问题向量化；本地无依据回复也按一次问答受理计数。次数不是计费次数。
- 一份真正开始建立或重建索引的文档占 1 次索引配额；批量 5 份最多占 5 次。
- 后端确认可直接复用的已完成索引，不重复占额或记录为新的模型任务。
- 上传、解析、删除、查看历史和读取用量不占这两类配额。
- 空知识库在调用供应商前直接返回无依据答案，记录为本地完成并明确“未调用模型”，仍计入已受理问答次数。
- 格式错误、权限不足、已有活动任务、重复 request_id、占额前发现配置缺失，不占额。
- 受理并提交占额后，即使失败、取消或断连也不退还次数。该规则保守防止重复尝试绕过保护，不表示实际产生了费用。
- 自然日采用固定 UTC+08:00，以受理时间归属当天；跨日完成不会扣第二天次数。
- 超额在发起外部请求前返回 HTTP 429，附 `code=daily_quota_exceeded`、任务类型和 `reset_at`。保留字符串 detail，兼容现有错误展示。

每日计数必须通过数据库条件更新原子占额，不采用进程内计数或先读后写。
占额、操作记录和现有任务受理在同一个短事务中提交；任何受理冲突应整体回滚。
数据库不可用时不放行外部模型调用。外部请求期间不持有数据库事务或行锁。
计数跨重启、跨进程有效；全局并发限制仍沿用现有机制，不将本模块宣称为新的分布式并发控制。

## 4. 数据结构与迁移

新增一条迁移，保持既有 0006 会话数据不变。

### usage_events

每个逻辑操作一条，记录：

- `id`、`user_id`、`request_id`、`operation`（chat/index）、`operation_run_id`、`quota_charged`、`quota_day`。
- 可空的知识库、会话、文档 UUID 快照；只保存标识，不新增指向这些资源的外键，删除资源不会级联删除账本，也不会引入资源外键锁与计数锁的倒序。账号外键采用删除级联，权限始终根据记录自身的 user_id 判断。
- `status`（running/completed/failed/cancelled/interrupted/local_completed）、受理时间、完成时间。
- 总耗时、检索阶段耗时、问题向量化耗时、回答模型耗时、校验耗时、索引处理耗时；不适用或未完成的指标为 null。
- 实际采用的对话和向量模型标识；供应商返回且经过校验的 prompt/completion/total token 数据及已知范围。
- 外部调用是否尝试、各阶段尝试次数、`error_code`；不存供应商原始错误响应。

`operation + operation_run_id` 唯一，结束操作按 running 状态条件更新，重复结束不会重复统计。
按 `user_id, started_at` 建立查询索引。使用适配 PostgreSQL/SQLite 的既有 UUID、JSON 和时间类型。

### daily_usage_counters

组合唯一键：`user_id, quota_day, operation`；字段包括非负 `used_count` 和更新时间。
插入冲突安全处理后，用 `used_count < limit` 的单条条件 UPDATE 完成占额，检查影响行数。
PostgreSQL 是并发正确性的验收基准，SQLite 用于大部分隔离测试，不用其结果代替 PostgreSQL 并发验收。

用量从本模块上线后开始记录。旧 messages 中的 usage 不回填成完整账本，避免遗漏失败调用造成误导。

## 5. 接入数据流

### 问答

身份和资源权限检查、请求去重及配置检查通过后，在现有 claim_chat_run 事务中登记操作并占额。
流式响应前完成超额拒绝，前端沿用 HTTP 错误展示，不生成一条假的失败答案。
执行中用单调时钟记录阶段耗时；供应商 usage 仅保留允许的非负整数指标。
答案校验、保存和 SSE 展示逻辑不变。完成、失败、取消均独立结束用量记录，不依赖浏览器持续接收。
会话被删除或任务租约失效时仍可关闭操作记录，不能通过删除会话清空已用次数。

### 索引

先执行现有权限、解析状态、活动任务和索引复用检查，再占额并提交 indexing 状态及操作记录。
失败仍兼容现有文档接口的 index_status/index_error 行为，但用量记录必须是 failed，不能按 HTTP 200 误算成功。
批量任务遇到 HTTP 429 自动停止后续任务，沿用已经实现的队列规则。

### 未正常结束的任务

清理达到既有任务最长执行时间并加宽限期的 running 记录，标记 interrupted，不退还配额。
按操作类型确定过期窗口；宽限期应覆盖当前索引和问答上限，正常任务不得被清理。
用量查询前以短事务幂等清理当前账号的过期记录，无需本模块新增调度器。
晚到的完成操作不得覆盖已经被确认过期的记录。

## 6. Token 与统计口径

- 对话 token 优先取供应商实际返回的 usage，不根据字符数伪造。
- 现有 Embedding 接口没有保留可靠 token 元数据；本模块未能可靠取得时显示“未知”，不记为 0，也不为统计额外请求模型。
- 问答中的向量化和回答模型分别标明已知/未知范围；可展示“已知 Token 合计”，但不能标成完整消耗。
- 供应商分批返回的 Embedding usage 只有所有已尝试批次数据可靠时才标为完整；部分已知值需保留“不完整”标识。
- 检索未命中、失败或取消均不自动推断零费用；仅明确未尝试供应商的阶段可以标为“未调用”。
- 不提供金额估算，不把本站次数或 Token 统计称为供应商账单。
- 成功率统计按 completed/local_completed 与已结束操作计算，进行中不进入分母；本地完成与模型调用另列。
- 平均耗时只使用有完整总耗时的已结束记录，显示样本数；已知 Token 合计同时显示用量未知的操作数。

## 7. 脱敏日志与请求编号

使用标准 logging 输出白名单 JSON 结构，并在请求、服务和异步任务之间显式传递请求编号。
请求编号由服务端生成，返回 `X-Request-ID`；浏览器不能通过自带头注入日志字段。
日志允许：事件名、请求编号、已认证账号 ID、资源 UUID、固定路由模板、HTTP 状态、阶段耗时、结果码和模型标识。
不记录问题、回答、文件名、文档正文、查询参数、Cookie、Authorization、密码、密钥、连接串或供应商原始响应。
业务异常只记安全错误码和异常类型，不直接序列化异常对象、SQL 参数或任意字符串。
SSE 的 HTTP 响应开始与流结束分别记录，不能把开始返回 HTTP 200 当作任务成功。
请求上下文在 finally 中恢复；业务任务携带自己的 request_id，不依赖已结束请求的上下文。
应用访问日志采用脱敏路由模板；项目启动指南关闭 Uvicorn 默认原始访问日志，以免其单独输出查询参数。

## 8. API 与前端页面

新增只读接口：

- `GET /usage/summary`：今日配额、已用/剩余、重置时间、近期汇总和数据起始时间。
- `GET /usage/events?operation=chat|index&status=...&limit=20&offset=0`：分页操作列表，不返回任何正文或其他账号数据。

汇总窗口固定为当天和近 7 个 UTC+08:00 自然日（今天及前 6 天），查询限制、排序和状态筛选均在后端验证。
页面置于 `/settings/usage`，侧栏新增“用量”。
顶部展示今日问答和索引剩余额度，下方为近期统计和可筛选的调用记录表格。
表格列为时间、任务类型、模型、结果、总耗时、已知 Token/完整性和请求编号；不显示问题或文件名。
包含空数据、加载、重试、分页、移动端和登录失效状态，不使用营销式版面。
超额时问答保留未提交的问题，索引保持原状态，明确显示重置时间；不自动重试或自动增加限额。

## 9. 验收与配置教学

1. 正常问答、索引、拒答、失败、停止和断连均能按口径追踪；不改变既有答案校验与展示行为。
2. 每日剩余 1 次时，跨会话或跨文档并发只允许一个任务占额；重启后计数仍在。
3. 重复 request_id、复用索引和拒绝请求不重复占额；任务在午夜前后运行不会跨日多扣。
4. 超额不调用模型，不创建新回答；批量索引收到 429 后停止未开始的文件。
5. 删除文档、会话或知识库不恢复配额、不抹掉用量汇总；不同账号不能相互查询。
6. 缺失 usage、部分阶段未知、索引 HTTP 200 但业务失败、后台过期任务均有独立测试。
7. 敏感哨兵字符串放入密码、问题、文档、查询参数和异常中，捕获日志断言其不出现。
8. 使用隔离数据库和模拟模型验证，不调用真实模型；PostgreSQL 专测原子占额与回滚。
9. 完成前运行后端测试、前端浏览器测试、类型检查及生产构建。
10. 提供迁移、后端重启和两项配额配置教学。助手不自行修改真实密钥文件或迁移用户数据库，用户执行并验收。
